# Тренажёр счёта

Девять разделов для начальной школы: сложение и вычитание, таблица умножения и
деления, состав числа, разрядный состав, ритмический счёт, часы, римские цифры,
фигуры. Семь языков интерфейса, настройки и статистика хранятся в `localStorage`.

Правило для генераторов: любой пример решается в уме, без черновика. Поэтому
стороны фигур не больше 10, римские цифры только читаются, а деления с остатком
пока нет.

## Запуск

Статическая страница на ES-модулях — нужен любой http-сервер. Через `file://`
модули браузер не загрузит, двойной клик по `index.html` не сработает.

```sh
python3 -m http.server 8000     # затем открыть http://localhost:8000/
```

Равнозначно: `npx serve` или `php -S localhost:8000`.

Отправка отчётов об ошибках так работать не будет: простой сервер статики не
выполняет `api/feedback.mjs` и на POST отвечает 501. Приложению это не вредит —
отчёт ложится в очередь. Чтобы проверять и функцию тоже, нужен `vercel dev`:

```sh
npm i -g vercel
vercel dev                      # статика и api/ как в production
```

Сборки нет: что лежит в репозитории, то и попадает на хостинг.

Имён файлов с хешами тоже нет, поэтому `vercel.json` велит браузеру сверять
каждый файл с сервером (`max-age=0, must-revalidate`). Без этого после деплоя
можно получить свежий `index.html` со старым `main.js` из кэша — страница
выглядит новой, а поведение остаётся прежним. Локально при правках
js и css перезагружайтесь с `Cmd+Shift+R`.

## Как добавить

- **новый режим** — файл в `core/`, запись в `GEN` (`core/index.js`), запись в
  `MODES` и список настроек в `OPTS` (`config.js`), значения по умолчанию в
  `DEF` и их проверка в `loadSaved()` (`state.js`), ключи во все три словаря `i18n/`.
  Статистика заводится сама — она собирается из `MODES`;
- **новый вид отрисовки** — файл в `view/` и запись в `VIEWS` (`view/item.js`).
  Рамку пропуска берите из `view/blank.js`, а не пишите заново;
- **нецифровой ответ** — положите в пример `choices` (значения) и `lk` (приставка
  ключа подписи). `screens/pad.js` сам покажет варианты вместо цифр, а
  `isRight()` сравнит строки. Так сделаны «название фигуры» и «найди лишнюю»;
- **новый язык** — словарь в `i18n/`, запись в `I18N` и строка в `LANGS`
  (`i18n/index.js`). Больше нигде правок не нужно: список языков, выпадающий
  селектор и проверка сохранённого значения берутся из `LANGS` и `CODES`.

Все словари `i18n/` должны содержать одинаковые ключи и одинаковые подстановки
вида `{n}`. Расхождение страницу не ломает (есть откат на английский), но текст
молча портится, поэтому стоит проверять:

```sh
node --input-type=module -e "
import {I18N,CODES} from './js/i18n/index.js';
const base=Object.keys(I18N.ru);
const ph=s=>[...String(s).matchAll(/\{(\w+)\}/g)].map(m=>m[1]).sort().join(',');
for(const l of CODES){
  const miss=base.filter(k=>I18N[l][k]===undefined);
  const broken=base.filter(k=>I18N[l][k]!==undefined&&ph(I18N[l][k])!==ph(I18N.ru[k]));
  if(miss.length||broken.length) console.log(l,'нет:',miss,'подстановки:',broken);
}
console.log('проверено языков:',CODES.length);
"
```

### Шрифты

Рукописная Neucha не содержит казахских букв (ә, ғ, қ, ң, ө, ұ, ү, һ) — слово
рисовалось двумя шрифтами сразу. Для казахского `--hand` переключается на Caveat
правилом `html[lang="kk"]`, она покрывает алфавит целиком.

Грузинских букв в Neucha нет вовсе, поэтому они уходят в Noto Sans Georgian
через цепочку шрифтов, а цифры в клетках остаются рукописными. Отдельного
правила для `ka` не нужно.

## Отчёты об ошибках

Кнопка «Сообщить об ошибке» есть на экране настроек и на экране итога — намеренно
не в игровом, потому что писать отчёт будет взрослый, а не ребёнок.

Уходит три вещи:

- **состояние** — режим, настройки, сам пример, что введено, последние ~20 шагов.
  Это главное: по нему экран воспроизводится точно;
- **снимок разметки** листа (1–8 КБ) — открывается в `tools/replay.html` с теми же
  стилями и выглядит в точности как у пользователя;
- **PNG** — чтобы увидеть отчёт, не открывая просмотрщик. Собирается через
  `foreignObject` со вшитыми шрифтами; если не собрался, отчёт уходит без него.

Если с примера уже ушли, снимок пересобирается из истории — иначе в кадр попал бы
экран настроек, а не то, на что жалуются. Имя и почта не спрашиваются.

При обрыве связи отчёт кладётся в `localStorage` и уходит при следующем запуске.

### Сервер

`api/feedback.mjs` — обычная serverless-функция Vercel: папку `api/` она подхватывает
и у статического проекта, Next.js для этого не нужен. Доступна по пути `/api/feedback`.

Расширение `.mjs` обязательно: без `package.json` файл `.js` на Node 18 и 20 считается
CommonJS и `export default` в нём не разберётся.

При импорте в Vercel: **Framework Preset — Other**, команды сборки и установки
оставить пустыми, Output Directory не трогать.

Переменные окружения:

```
GITHUB_TOKEN   обязательно: токен с правом issues:write и contents:write
GITHUB_REPO    владелец/репозиторий — нужен, только если проект не связан
               с GitHub: иначе берётся из системных VERCEL_GIT_*
MEDIA_BRANCH   ветка для картинок, по умолчанию feedback-media
```

Связь проекта с GitHub не заменяет токен: она нужна, чтобы код попал из репозитория
на хостинг, а токен — чтобы функция обратилась к GitHub в обратную сторону.

Версия кода в задаче берётся из `VERCEL_GIT_COMMIT_SHA`, так что по отчёту видно,
на каком именно коммите он снят.

Картинки коммитятся в отдельную ветку и вставляются в задачу raw-ссылкой: в историю
кода они не попадают. Задача создаётся даже если картинку залить не удалось.

Сменить транспорт (Formspree, Supabase, свой сервер) — это правка `js/feedback/send.js`,
остальной код её не заметит. При переезде на Next.js тело `handler` переносится
в `app/api/feedback/route.js` почти без изменений.

**Чего пока нет:** защиты от спама. Эндпоинт открытый, ограничены только размер
отчёта (2 МБ) и картинки (400 КБ). Если польётся мусор — Cloudflare Turnstile
или проверка Origin на стороне функции.

## Подвал

`js/screens/footer.js` — копирайт с текущим годом и контакты. Прижат к низу:
`body` это сетка `1fr auto`, поэтому на короткой странице подвал стоит у нижнего
края экрана, а на длинной уезжает вместе с содержимым. Во время решения примеров
он скрыт (`body.playing`) — там экран занят клавиатурой и лишняя строка ломала бы
раскладку на телефоне.

Контакты задаются константами в начале файла:

```js
const OWNER='AlekseiGrinDev';                                  // Telegram по нику
const WHATSAPP='alekseigrindev';                               // имя, номер или ссылка
const LINKEDIN='https://www.linkedin.com/in/alekseigrindev';   // ссылка целиком
```

Ссылка поддержки живёт не здесь, а в шапке — см. ниже.

Новый контакт — запись в `LINKS` с именем, адресом и путём иконки в системе
координат 24×24. Контакт с пустым адресом не выводится.

С 2026 года WhatsApp понимает имена пользователей: `wa.me/<имя>` перенаправляет
на `api.whatsapp.com/send/?username=…&type=username`, а `wa.me/<цифры>` — на
`…?phone=…&type=phone_number`. Вид строки сервис определяет сам, разбирать её
в коде не нужно. Имена пользователей только строчными.

Перенаправление не проверяет, существует ли имя, — это выясняется уже
в приложении. Пустая константа означает, что ссылка не выводится.

## Шапка и тема

Шапка (`.site-header`) лежит вне `<main>` — это обрамление страницы, а не её
содержимое. Слева апельсин и название, справа кнопка «покормить котов», выбор
языка и переключатель темы.

Кнопка поддержки (`.feed` в `index.html`) — статичная разметка с эмодзи 🐈.
Фирменную жёлтую картинку Buy Me a Coffee не берём: она тянет сторонний запрос
и выбивается из оформления «тетради».

Внимание к адресу: `buymeacoffee.com/<имя>` — страница поддержки, а
`buymeacoffee.com/invite/<имя>` — приглашение других авторов в сервис.

На экранах уже 560px подпись кнопки прячется, остаётся значок; смысл несут
`aria-label` и всплывающая подсказка — их проставляет `applyStatic()` по
атрибуту `data-i18n-label`. Уже 360px вся шапка переносится в две строки.
На телефоне во время решения примеров шапка скрыта: экран там отдан под пример
и клавиатуру.

Описание проекта (`lead`) подставляется в `meta name="description"` и
переводится вместе с интерфейсом, так что ссылка на сайт разворачивается на
нужном языке.

На первом экране над вкладками есть отдельная строка `intro` — чем приложение
является и для кого. Она видна, **пока ребёнок ещё ни разу не занимался**
(`progress.food === 0`): пришедшему по ссылке родителю надо объяснить, что
это, а возвращающемуся ребёнку эта строка уже мусор. Отдельной кнопки
«скрыть» поэтому не нужно.

Тема: пока человек не выбрал сам, `S.theme === 'auto'` и всё решают правила
`@media (prefers-color-scheme)`. Явный выбор ставит `data-theme` на `<html>`
и перебивает системную настройку. Начальное значение атрибута выставляет
маленький скрипт в `<head>` — без него страница с сохранённой тёмной темой
успевала мигнуть светлой до загрузки модулей.

Осторожно с именами классов: `.topbar` — это строка с кнопкой «К настройкам»
на экране решения, к шапке сайта она отношения не имеет.

## Экран решения

Сверху строка состояния: «1 / 10» и секундомер. Слово «Пример» убрано с экрана,
но осталось в `aria-label` счётчика — для чтения с экрана «1 / 10» слишком немо.

Прогресс — сплошная полоса с делениями по числу примеров. Россыпь квадратиков
при 20 примерах переносилась на две строки; деления сохраняют ту же информацию,
но читаются как один объект.

Выход из раунда — кнопка под клавиатурой, с увеличенным отступом: она не должна
восприниматься как пятый ряд клавиатуры и ловить случайные нажатия.

Секундомер считает вверх и останавливается и на итоге, и при выходе
(`stopClock()` в `finish()` и `quit()`), иначе интервал продолжал бы тикать.

## Аналитика

Тег Google Analytics (`G-85P8ZRTRNL`) стоит в `<head>` файла `index.html`,
после скрипта темы: тот должен успеть до первой отрисовки, а тег асинхронный
и рендеру не мешает.

Два места, о которых стоит помнить:

- **Запуски с localhost попадают в ту же статистику.** Отсеять можно либо
  фильтром на стороне GA, либо условием вокруг тега на странице.
- **Заголовок страницы переводится**, поэтому в отчётах одна и та же страница
  будет встречаться под семью названиями. Адрес при этом один, так что
  группировать лучше по нему.

## Иконки

`favicon.svg` — тот же апельсин, что в шапке, но отдельным файлом: переменные
темы страницы в иконку не достают, поэтому цвета заданы явно, а тёмный вариант
подключается через `@media (prefers-color-scheme:dark)` внутри самого SVG.
Блик из шапки убран — на 16 пикселях он превращался в грязь.

Растровые запасные собраны из того же SVG отрисовкой на холсте, без сторонних
утилит. Если править апельсин, `favicon.png` и `apple-touch-icon.png` нужно
пересобрать: они не обновляются сами.

## Награды

Школьная отметка (`5`/`4`/`3` и «Ещё потренируемся») убрана. Вместо неё звёзды,
и нижняя граница — **одна звезда за пройденный раунд**: тренировка это место,
где ошибаться не страшно, а «3» за старание отбивает охоту возвращаться.
Вторая даётся при 70 % верных с первой попытки, третья при 90 %.

Корм (`progress.food`) начисляется **за каждый решённый пример, независимо от
числа попыток** — за усилие, а не за точность. Награда за точность обходит
стороной того, кому тренировка нужнее всех.

`progress.days` хранит, сколько решено в каждый день (последние 180). Дата
берётся местная, не UTC: иначе занятие поздним вечером попадало бы в следующий
день и серия рвалась бы на ровном месте.

Из этого считаются **серия дней** и **дневная цель** (`streakDays()`,
`solvedToday()` в `js/state.js`). Вчера считается живым днём: если сегодня ещё
не занимались, серия не обнуляется — день не кончился. Серия никогда не
показывает «потеряна», только текущее число, и прячется при значении меньше
двух: один день это ещё не серия.

Цель на день — общая настройка (10 / 20 / 30, по умолчанию 10, то есть один
раунд). Настройки с `global:true` в `js/config.js` пишутся в `S`, а не в конфиг
раздела; раньше это было захардкожено по имени ключа `count` и новая общая
настройка молча уходила не туда.

Корм и дни проверяются при загрузке по отдельности: мусор в хранилище
отбрасывается, страница не падает.

## Коллекция котов

`js/cats.js` — пороги и окраска, `js/view/cat.js` — рисунок, `js/screens/cats.js`
— экран. Восемь котов, пороги 10 / 25 / 50 / 90 / 140 / 210 / 300 / 420 корма:
первый приходит за один раунд, восьмой примерно за полтора месяца при одном
раунде в день.

Коты даются за **общий корм, а не за отдельные разделы**: привязка к разделам
толкала бы ребёнка туда, где кот ещё не получен, вместо того, что ему надо
тренировать.

Все восемь — **одна фигура с разной окраской и отметинами**, а не восемь
силуэтов: узнаваемость даёт поза. Запертые показываются силуэтом с порогом —
видно, что будет дальше и сколько осталось.

Новый кот показывается сразу на экране итога, а не ждёт, пока ребёнок сам
зайдёт в коллекцию. Вход в коллекцию — по счётчику корма в строке «сегодня».

## Почему ничего не прыгает

Экран решения специально сделан так, чтобы между примерами ничего не меняло
размер и положение: ребёнок целится пальцем в клавишу, и уехавшая под рукой
клавиатура — это промах.

- **Размер клетки задаётся один раз на раунд.** `fitRound()` в `js/view/item.js`
  берёт максимум по всем примерам раунда, а не считает на каждый. Раньше при
  смешанных настройках `--n` скакал 10 → 12 → 14, и на телефоне цифры меняли
  размер примерно на 40 %.
- **Высота листа тоже задаётся на раунд.** Та же функция прогоняет все примеры
  через невидимый образец, берёт наибольшую высоту и ставит её как `min-height`.
  Образец кладётся рядом с настоящим листом, а не в `body`: на телефоне у листа
  внутри игрового экрана своё правило `--cell`. Без этого в «составе числа»
  вперемешку клавиатура прыгала на 165 пикселей.
- **Галочка «✓» нарисована всегда**, но прозрачной (`.eq::after`), и зеленеет
  при верном ответе. Раньше она дорисовывалась и пример менял ширину прямо на
  том же шаге.
- **Рамки с ответом не растут при наборе** там, где они стоят по центру: у часов
  обе всегда по две клетки, у фигур — `minCells:2`. Иначе набранная цифра
  уезжала из-под пальца.
- **Под сообщение зарезервированы две строки** (`.msg{min-height:3rem}`). Одной
  не хватало, и длинный текст опускал клавиатуру на 22 пикселя.

Если добавляете новый вид примера — прогоните раунд и убедитесь, что высота
листа и верх клавиатуры не меняются от шага к шагу.
